# 实现审查 (Step 4)

> **用途**: 在代码实现完成后、质量检查前，触发正式的实现审查流程
> **对应工作流步骤**: [workflow.md Step 4](../rules/workflow.md#step-4-实现审查)
> **阻塞级别**: ★ 必须用户确认

## 触发时机

- 代码开发完成（Step 3 结束）
- Bug 修复完成
- 重构完成

---

## 审查流程

### 第一步：收集上下文

```
请 AI 执行以下操作：

1. 列出本次任务的所有变更文件清单（含新增/修改/删除）
2. 对每个变更文件，展示：
   - 文件路径和变更类型
   - 变更行数统计（+/-）
   - 一句话描述变更目的
3. 展示原始改动计划（来自 Step 2）
```

### 第二步：逐项对照

```
对照原始改动计划，逐项标记：

| 计划项 | 状态 | 说明 |
|--------|------|------|
| [计划项1] | ✅ 符合 / ⚠️ 偏差 / ❌ 阻塞 | ... |
| [计划项2] | ✅ 符合 / ⚠️ 偏差 / ❌ 阻塞 | ... |

状态说明：
- ✅ 符合：完全按计划实现
- ⚠️ 偏差：有差异但可接受（需说明原因）
- ❌ 阻塞：必须修复的问题
```

### 第三步：范围外检查

```
检查是否存在超出原计划的额外改动：

- 是否修改了未在计划中的文件？
- 是否引入了未计划的依赖？
- 是否改变了未涉及的模块行为？

如有，逐一列出并评估影响。
```

### 第四步：功能验证

```
对核心功能点进行逻辑走查：

1. 正常路径是否正确处理？
2. 边界情况是否考虑？
3. 错误处理是否完善？
4. 是否引入了安全风险？
5. 性能是否有明显退化？
```

### 第五步：输出审查报告

```
## 实现审查报告

**任务**: {任务名称}
**日期**: {YYYY-MM-DD}
**审查人**: AI ({model})
**用户确认**: [ ] 等待中 / [x] 已通过 / [x] 有条件通过

### 变更概览
- 新增文件: N 个
- 修改文件: N 个
- 删除文件: N 个
- 总变更量: +N/-N 行

### 计划符合度
| 计划项 | 状态 |
|--------|------|
| ...    | ...  |

### 范围外变更
| 变更 | 影响 | 处理建议 |
|------|------|---------|
| ...  | ...  | ...      |

### 发现的问题
| # | 严重度 | 描述 | 建议 |
|---|--------|------|------|
| P0 | 阻塞  | ...  | ...  |
| P1 | 重要  | ...  | ...  |

### 审查结论
[ ] 通过 → 进入 Step 5 质量审查
[ ] 有条件通过 → 修复以下问题后进入 Step 5:
[ ] 不通过 → 回到 Step 3 修复
```

---

## 用户操作指南

收到审查报告后：

1. **仔细阅读**所有变更项和问题列表
2. 如有问题需要解释 → 直接回复，AI 会补充说明
3. 如需修改 → 指出具体项，AI 回到 Step 3 修复
4. 确认无问题 → 回复"审查通过"或"OK"

> ⚠️ **重要**: 未获得用户明确确认前，禁止自动进入下一步骤。
